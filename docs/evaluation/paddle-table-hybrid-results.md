**本轮不采用该候选。**B比A低20.73个百分点，C比A低26.43个百分点。C相较B正确项没有增加，误提取增加46项，局部复核在错误结构上反复读取并未改善最终结果。

## 为什么退化

原生PP模型仅在三页检测到表格：一页HTML有84个单元格但只有82个框，适配器拒绝；另两页转换得到86/27个单元格，却都只恢复出2列，名称列和金额列无法由原文表头可靠定位。其余四页未检测到表格，明确回退原OCR。

已目视核对其中一张原图实际有7列。因此至少这一页的列关系错误已存在于PP原生HTML中，不是评分器造成。两张表分别有53/17个单元格的文字与几何匹配需复核。不能仅凭单元格数与框数相同就认定结构可信。

已有局部VLM逻辑依赖可信行列与来源单元格。在列关系不成立时，裁剪和金额绑定也缺乏可靠依据。C最终没有产生`verified_cells`或`verified_amount_visual_name`费用行，输出仍为待核对或未验证状态；没有发布为医学审核通过结果。

本轮并未完整适配所有表格类型或对PP进行微调，因此不能宣称所有“OCR＋结构＋VLM”架构都会更差。它否定的是当前模型、预处理和接入条件下的候选。

## 结果后的保护修复

原始A/B/C记录保留，表格缓存版本为`paddle-v5-gpu960-tablemagic-v1`。根据上述失败，适配器增加名称列/金额列接入门槛：二者都必须唯一且互不重叠，否则记录`ambiguous_fee_columns`并回退原OCR。新版缓存标记`paddle-v5-gpu960-tablemagic-v2-column-gate`，使用新目录，不覆盖原实验。

该门槛是在看过本次结果后增加的保护修复，不冒充预先冻结的实验条件。门槛检查只是拒绝不可信结构，不代表提高了模型识别精度。其产物在`paddle-table-hybrid7-gated-ocr/`和`paddle-table-hybrid7-gated.json`。门槛实跑后七页均回退：2表因列无法定位被拒绝，1表因HTML/框数不一致被拒绝，4页未检出表。传给抽取器的text、lines和tables已逐项比较，与原PP缓存完全相同；没有再调用LLM，不另报一个“修复后F1”。

下一轮应先验证费用表裁剪、倾斜处理和较高有效分辨率下的文字/结构质量，再考虑局部VLM。不能在不可定位的行列上继续增加复核调用。
