# 四项抽取 Skill 与全量评测协议

## 已接入的运行链路

`scripts/preliminary_kr1.py` → `document_fields.extract_document` → 初次字段/费用抽取 → `extraction_skills.review_extraction` → 证据绑定 → 费用语义分类 → 原有评分器。

本次接入 KR1 文档级实际抽取入口，未接入患者端上传入口，未部署生产。四份 `skills/extraction-*/SKILL.md` 由运行时按需读取，其内容及运行模块均纳入预测的实现指纹。不是仅给 Codex 阅读的说明文件，也不是不限次数的自主代理。

1. **原文保真与字段拆分**：`detailName` 保留完整名称单元格，包括其中的规格、前缀、括号与编号；独立列不拼接。`normalized_detail_name`、`specification`、`source_billing_codes` 仅为派生字段。证据绑定中的编码处理也不再覆盖原文名称。
2. **费用行列对齐**：首次抽取和复核均加载物理行、表头、总金额列、换行名称与真实重复行规则。未经单元格证据证明的行绑定使风险调度分数最高为 0.8，不能仅凭模型报 0.99 跳过复核。
3. **低置信度复核**：风险启发式合并字段自报分、可匹配 OCR 文本的识别分、名称/金额引用支持、原名冲突、绑定状态及明确的数量单价矛盾；低于 0.85 触发。这个分数不是经校准的正确概率。每页一轮语义复核，提供整页以及最多四个最弱候选的原图条带，条带覆盖邻行及各列。候选使用原图坐标，不把旋转后裁剪坐标当原图坐标。
4. **完整性核对**：对有费用表的页面独立核对首尾行、漏行、疑似重复/小计；可补有原图框和完整引用的新行。相同名称金额的新行有歧义时标记待人工，不靠文本去重自动删行。观察行数与最终行数不一致会标记未解决。观察行数及 `coverage_complete` 仍为模型自报，不是人工已验证的覆盖率。

PP 文本 OCR 没有原生单元格绑定证明，因此可能触发大量费用行复核；这版优先验证效果，未声称已实现最少调用成本。

## 复核边界

- 更正仅限风险候选行和低分字段，新增行仅限检查到费用表的页面。每个费用更正/新增需通过原有 `FeeItem` schema、新值自报分至少 0.9、完整名称与金额引用检查，并携带合法原图框和原因；这些条件仍不能代替人工真实性验证。
- 字段更正保留证据、原因和原图框，最终整份预测重新经过原有 schema 校验。接受的更正前后值、补行和未解决项写入 `skill_review`。
- 语义复核失败时原子地保留首次结果，不因复核失败抹掉已抽取字段。不能为得到满意内容循环调用。传输错误的有限重试另记在 `stage_request_attempts`，与一次语义复核区分。
- 不自动删除疑似重复或小计，不根据合计倒算未见项目，不使用参考答案指导 Agent。
- 检测到未解决费用问题时标记部分完成，评分仍保留其已观察字段；失败、缺失页仍计 FN，不从全量分母移除。
