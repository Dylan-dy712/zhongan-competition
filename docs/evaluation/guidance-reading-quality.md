# 温度指引的阅读验收

报告生成成功、引用有效和模型阅读质量检查通过，不代表 KR3 的真人温度评分达标。

## 开发检查

输入必须包括本次可读病历证据、原文可定位的痛点候选、授权用户表达和相关知识来源。痛点候选不得写成已确认的医疗过错。覆盖诊断通俗解释、治疗经过与一般目的、费用含义、可执行康复安排、具体关切回应和下次就医准备。

解释可以使用有出处的一般知识；个人诊断、用药剂量、活动强度、复诊日期与治疗改变必须保留个体医嘱依据。模型阅读检查评价患者实际看到的正文，事实复核另行执行。阅读检查失败最多改写一次，仍不充分则记录失败原因。两类检查的调用和 token 均需记录。

三个合成开发场景：骨折与电脑录入工作的恢复顾虑；肺炎出院后的术语理解与通勤顾虑；糖尿病与轮班工作的记录安排。合成场景用于调试，不替代官方脱敏测试集或真人评价。

## 真人盲评

在授权范围内选取至少三个病种的独立脱敏样本。对同一案例生成旧版与新版内容，随机显示为 A/B，隐藏模型与版本。不得把用于调试的合成样本当作正式独立验证。

每份内容建议由至少三名独立读者评分。普通读者评价以下项目，医学评审者另核验事实、适用条件及安全。

- 温度感：回应真实关切、尊重用户、减少不确定感，无虚构情绪或效果保证。
- 可行动性：用户知道接下来准备什么、记录什么、向谁确认什么；行动有依据且能执行。
- 解释清晰度：读者能用自己的话说明关键术语、本次治疗与费用含义。
- 个性化：内容对应本次病历、治疗阶段和实际生活限制，换一个病例不能直接套用。

各项按 1–5 分评分：1 分无法理解或使用，3 分部分帮助但仍需补充，5 分解释清楚且有具体可执行帮助。记录每位读者原始评分和一句理由，不用模型自评分代填。

汇总温度感与可行动性的平均分、样本数、病种覆盖、评审人数和分歧。达到 4/5 前不得声称 KR3 已达标。出现医学事实或个体治疗错误时应单独记录，不能由温度高分抵消。
