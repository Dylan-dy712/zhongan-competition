# 新 KR 前端优化（2026-10-12）

依据：本次用户提供的新指标截图及逐项确认的交互方案。本轮以截图为考核口径，不把旧版专家一致率或真人盲评额外要求写成新指标；保留现有医学审核、发布、主体授权边界。

## 行为与数据契约

1. 图片先进行授权下的临时预检，再正式登记。按可识别标题推测材料类型；模糊、分辨率低、低 OCR 置信度逐张提醒。替换仅更新待提交文件，同一位置只登记最后确认的一张。预检不落盘、不登记文档；OCR 不可用明确提示，用户可重试或继续。
2. OCR 正式解析保留原始行作审计，置信度低于 0.8 的行暂不进入事实抽取与叙述证据。可读部分继续处理。该阈值是待用代表性照片校准的保守工程阈值，不是准确率承诺。
3. 叙述新增 `citations: [{quote, source_refs}]`。quote 是去掉加粗后的唯一单行原句；引用必须属于当前授权材料或实际检索知识。生成时绑定、服务端校验、独立原文复核核对引用支持关系。保留既有全文来源集合用于校验，不由前端猜测句子与来源。
4. 新报告使用正文上标。历史未绑定报告提示重新分析，不伪造逐句引用。来源面板显示文件名、页码、摘录；有 bbox 的原图显示定位。专业知识显示原有标题、出处、版本、适用范围与内容；不补造页码。
5. 新增 `overview` 路由：病历摘要、需要关注、康复指引、就医参考。病例事实带原文状态与否定/疑似/既往限定，JSON 按本次 run 导出。临床待审核项明确待核对。
6. 新增 `demo` 路由：三个合成病种材料通过真实分析链路运行；机构演示是纯函数合成统计，不写入业务快照，不生成真实排名。
7. 机构画像按实际快照分组选择，至少两项需求，最多三家对比。结果快照与展示快照不一致时要求重新加载。未选择适用分组时不自动提交通用病种请求。

## 新增接口

- `POST /v1/materials/inspect`：multipart 图片及 subject_id；检查前后校验授权；仅返回质量提示与短摘录。
- `GET /v1/cases/{case_id}/material-quality?run_id=...`：本次运行的页级质量提示。
- `GET /v1/knowledge/{entry_id}`：登录后的专业参考知识详情。
- `GET /v1/quality/demo` / `POST /v1/quality/demo/recommendations`：明确合成来源的 3 病种 × 5 机构画像与两条以上需求理由。
- `POST /v1/conversations/{conversation_id}/documents/{document_id}/replacement`：原件与替换件保持同案件；重试去重，过期目标返回 409，保留历史依据。新分析只选择未被替换的材料。
- Evidence 增加 source_name、document_type、media_type，旧调用向后兼容。

## 验收与限制

- 前端 TypeScript/生产构建、登录导航回归、图片替换交互、逐条引用、病例切换/异步返回、手机及桌面溢出检查。
- Python 覆盖图片分类不确定性、OCR 失败、模糊金额隔离、引用跨来源/重复锚点拒绝、三病种画像覆盖及无排名。
- F1、关键字段缺失率和痛点实际覆盖需在固定材料集上另行实测；UI 和合成统计不构成官方 KR 已达标的声明。
- 本轮不部署服务器。部署前须执行 022_document_replacements.sql；已登记材料通过专用 replacement 接口替换，保留原件和旧证据，新的分析与发布只使用有效材料。普通补传仍是新增资料，不自动猜测替换关系。

- 显式重新分析使用 force_new，按当前请求的时间边界复用重试任务；来源生成请求按提示词版本幂等。
