# 评委示例资料：体验真实上传与识别

评委体验账号可从首页进入上传流程，在资料准备页选择“导入示例病例”。样例包含两页出院记录、两页费用明细和一页医保结算信息，整理为三份 PDF；保留医疗与费用正文，进一步遮盖姓名、住院号、检查编号及结算身份信息。副本只嵌入脱敏后的可见像素，不能移除遮盖还原原图。PDF 页尺寸保留现有 Worker 按 2 倍渲染时的原图分辨率。

选择示例时，浏览器读取受保护的样例文件并放入待上传列表，同时按已核对的材料预填诊断、日期、总费用等申请字段。此时没有创建账号病例、注册文档或启动分析。评委可以预览、移除文件、核对申请信息，再明确确认提交。

确认后复用原有 multipart 上传接口，页面显示实际文件上传进度，失败重试保留成功上传的文件和申请标识。上传完成后，评委点击“查看相关报告”才调用现有异步分析接口，由 Worker 解析 PDF、识别扫描页、提取事实并生成材料分析与关怀文本。每次新提交建立独立案件；不会使用预先生成的报告代替处理流程。

三份资料由服务器私有目录提供，`/judge/sample` 与文件下载只允许 `judge_demo_slots` 中的已登录账号访问；下载还检查资料用途授权。主站继续默认只接收合成案件，仅为这些账号、本次已核对的样例开放 `official_deidentified` 来源。案件保存样例标识及“非账号使用者病史”的说明；该来源下的上传必须匹配已核对文件的 SHA-256，不能把任意文件标为主办方样例。这些体验副本不是新增官方评测样本，效果评测仍使用既有冻结清单。

维护人员使用 `python -m scripts.upload_judge_sample --host <host> --key <本机私钥> --sample-dir <已核对的样例目录>` 上传私有资产。目录需包含 `manifest.json` 和清单中的 PDF，文件名、哈希、大小及不可变版本在本地和远端核验。活动样例通过私有目录链接供主站读取，不向主站进程加载体验邀请码。病例文件、选择清单、预览图和生成文件不提交到代码仓库，位于忽略目录 `output_dir/judge-sample/`。

验证包含 `node apps/web/scripts/check-judge-upload.mjs` 的选择无写入、预览与确认、真实 multipart 请求、上传中断恢复、成功后才分析；以及独立 PostgreSQL schema 中的真实下载→上传→排队、文件来源校验、账号隔离与授权撤回。正式发布遵循现有 CI 和确切 main 版本部署流程；上线后再做手机尺寸浏览器端到端验证。
