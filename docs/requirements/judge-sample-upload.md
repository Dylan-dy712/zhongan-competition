# 评委示例资料：体验真实上传与识别

评委体验账号点击首页“开始评委体验”后，直接使用该测试账号的本人资料进入理赔申请页，自动填好申请字段并准备示例材料，不再需要选择人员或手动导入。申请页不显示重复的“没有病例资料”卡片。当前样例包含两页出院记录、一页诊断证明、五页住院费用明细及五页门诊与复诊病历，整理为四份 PDF，共十三页。选用清晰白底文档，保留医疗与费用正文，进一步遮盖页眉与正文中的患者姓名、证件号、电话、出生日期及院内标识。手写说明因清晰度较低而不纳入。原始资料未提供独立医保结算单或正式发票，不将其描述为已经齐备的正式理赔材料。副本只嵌入脱敏后的可见像素，不能移除遮盖还原原图。PDF 页尺寸使现有 Worker 按 2 倍渲染时得到整理后的完整页面像素；超大临床页面在保留文字清晰度的情况下限制长边为 3200 像素，避免无谓传输。

选择示例时，浏览器读取受保护的样例文件并放入待上传列表，同时按已核对的材料预填诊断、日期、总费用等申请字段。此时没有创建账号病例、注册文档或启动分析。评委可以预览、移除文件、核对申请信息，再明确确认提交。

申请字段立即填好，文件准备期间显示进度并暂缓进入下一步；载入失败可重试。返回首页后再次进入同一未提交的体验会保留已修改的信息与已准备材料，避免重复下载。切换账号不会沿用旧账号的体验入口状态；普通提交入口继续使用原有人员选择和空白申请表。

确认后复用原有 multipart 上传接口，页面显示实际文件上传进度，失败重试保留成功上传的文件和申请标识。上传完成后，评委点击“查看相关报告”才调用现有异步分析接口，由 Worker 解析 PDF、识别扫描页、提取事实并生成材料分析与关怀文本。每次新提交建立独立案件；不会使用预先生成的报告代替处理流程。

聊天中将申请表自动生成的分析请求显示为“材料已提交 · 暖暖为你整理”，不展示内部指令、申请字段 JSON 和重复的附件文件名列表。该展示也适用于已保存的普通申请与评委体验对话；后台仍使用完整申请字段、材料分类和样例来源说明，普通用户手写消息及其附件照常显示。

样例资料由服务器私有目录提供，`/judge/sample` 与文件下载只允许 `judge_demo_slots` 中的已登录账号访问；下载还检查资料用途授权。主站继续默认只接收合成案件，仅为这些账号、本次已核对的样例开放 `official_deidentified` 来源。案件保存样例标识及“非账号使用者病史”的说明；该来源下的上传必须匹配已核对文件的 SHA-256，不能把任意文件标为主办方样例。这些体验副本不是新增官方评测样本，效果评测仍使用既有冻结清单。

维护人员使用 `python -m scripts.upload_judge_sample --host <host> --key <本机私钥> --sample-dir <已核对的样例目录>` 上传私有资产。目录需包含 `manifest.json` 和清单中的 PDF，文件名、哈希、大小及不可变版本在本地和远端核验。活动样例通过私有目录链接供主站读取，不向主站进程加载体验邀请码。病例文件、选择清单、预览图和生成文件不提交到代码仓库，位于忽略目录 `output_dir/judge-sample/`。

验证包含 `node apps/web/scripts/check-judge-upload.mjs` 的选择无写入、预览与确认、真实 multipart 请求、上传中断恢复、成功后才分析；以及独立 PostgreSQL schema 中的真实下载→上传→排队、文件来源校验、账号隔离与授权撤回。正式发布遵循现有 CI 和确切 main 版本部署流程；上线后再做手机尺寸浏览器端到端验证。

示例下载允许 120 秒完成读取，页面显示已准备的文件数量；读取中断会给出可重试的中文提示。每份下载绑定清单版本，后台继续校验该不可变版本的哈希，确保更新或压缩资料时，已选择旧版文件的评委仍能完成上传。压缩后的样例保持原始页面像素分辨率并逐页核对正文清晰度。

不同病例使用不同样例标识。每份下载同时绑定样例标识及版本，已选择的旧病例继续按同一私有目录中的已核对清单校验，不能替换成新病例文件。诊断证明与门诊病历归入病历类，费用清单归入票据与费用类；原文无法确认的出险原因、医保结算及其他赔付字段保留为“待确认”。
