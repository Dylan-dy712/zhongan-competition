# 持续丰富的就医记录与疾病历程

用户确认的规则：同一次治疗及后续复诊归为一份就医记录；同一种病的新发作单独建记录，并关联到同一疾病历程。新的独立意外或其他疾病分别记录。

## 归档行为

- 原始案件、材料、报告版本和证据不迁移、不覆盖。新增的逻辑归属将多个资料批次展示在同一份记录中，每份报告仍独立可读。
- 成功完成分析后排入独立归档队列。Worker 使用独立线程及连接处理，归档模型失败不改变报告分析状态。GET 记录接口不触发模型调用。
- AI 按当前用户、当前成员的有效授权资料判断 `same_episode`、`follow_up`、`new_episode`、`uncertain` 或 `mixed`。同病名、同医院、上传时间相近都不单独构成合并依据。
- 自动归并要求可核对的双侧原文证据、足够明确的模型判断、共同的就医日期或就诊标识，且无明确的诊断或日期矛盾。复诊还必须有明确的接续治疗表述。模型置信数值仅为保守门槛，不是经过校准的医学准确率。
- 诊断、机构、就医日期、资料类型、就医经过均来自本批材料的逐字片段，引用必须属于该次分析。疑似、否定、既往限定不得省略；无法核对的字段不进入画像。
- 画像从同份记录内仍有效的各批资料累积：优先展示最近提供的字段，缺少的字段可保留早期材料的依据。新资料使旧分析过期时，旧画像暂不作为当前已核对信息展示。
- 模糊关联和一批资料混有多次独立就医时保留待确认状态。当前版本不自动把同一批混合材料拆分成多份独立病例。
- 用户可以逐批调整为“归入已有记录”“单独保留”或“仅关联，不合并”；校验版本防止旧页面覆盖新归属，后续 AI 分析不会撤销已确认的归属。
- 历史资料通过“智能整理已有记录”按当前成员排队整理；不在迁移中批量调用模型。新报告自动排队。无材料的普通对话不产生就医记录卡片。

## 权限与一致性

新迁移为 `023_medical_records.sql`。记录、归属、任务及审计单独存储。跨账号、跨成员、撤回或过期授权的记录不可作为候选或人工调整目标；相关记录链接也只返回当前可访问记录。模型调用结束后重新核对当前分析、材料哈希及授权，过时任务不应用到记录。

主要接口：`GET /v1/medical-records?subject_id=...`；`POST /v1/medical-records/organize`；`PATCH /v1/medical-records/cases/{case_id}`。调整请求包含 `mode`、可选 `target_record_id` 和 `expected_version`。

页面中的“我的 → 最近就医记录”与记录详情共用累积画像。记录详情提供资料更新顺序、每批的原报告入口、来源查看、归属确认，以及相关但单独保留的其他就医。

## 验证

`tests/test_medical_records.py` 使用模型替身与随机隔离 PostgreSQL schema，覆盖补充资料、复诊、新发作、独立摔伤、同病名不足以归并、来源伪造、疑似限定、家人隔离、授权撤回、原资料保留、版本冲突、人工归属保持、模型失败不影响报告及读取不触发生成。

`npm run test:medical-records` 覆盖实际 React 页面中的累积画像、独立关联记录、原报告/证据、归属确认、历史整理、错误恢复和成员切换的过时响应。构建与现有导航、授权、提醒和就医内容回归一并执行。
