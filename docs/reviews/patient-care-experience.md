# 患者端关怀体验

实际患者应用位于 `apps/web`，复用 `codex/frontend-care-pages` 的暖色视觉和已有插画，并继续使用原聊天、上传、证据、报告、回执与反馈接口。`/mobile-demo/` 保持独立合成演示，不代表已连接真实服务。

## 页面与契约

- 首页展示当前对话标题、真实分析状态、已发布指引及优先行动。行动必须属于当前报告，角色为患者/照护者，状态未结束，且有来源引用；无明确来源的时间显示“时间待确认”。不将建议画成已完成任务。
- 报告按六类内容展开阅读，仅显示 published、有合法报告版本且审核允许的声明。原始证据采用原生模态对话框，支持 Escape、关闭按钮和焦点限制；未知页码明确待核对。反馈仍绑定报告 ID/版本，待处理不表示已解决。
- 记录按照 case_id 分组和带时区的 updated_at 排序。页面统计资料组和对话数，不把它们推断成就医次数、病种或康复情况。切换记录清空旧报告、证据、输入及附件。
- 当前病例请求返回 401/403/404 时清空医疗缓存并使旧请求结果失效；401/403 重新连接，404 重新获取可见记录。前端隐藏不替代后端逐请求授权。
- 问暖暖仍使用现有真实消息、上传和分析续接逻辑；此改动不增加模型回退、定时模拟进度或额外 API 客户端。

## 验证范围

`npm run build --prefix apps/web` 完成 TypeScript 与 Vite 构建。`node --experimental-strip-types scripts/check_care_presentation.mjs` 验证未发布/待审核内容隐藏、跨报告与非患者行动过滤、未知时间、病例分组及带时区排序；该检查进入 GitHub CI。

2026-10-03 使用正常 React 应用和仓库外本地合成 HTTP 契约服务，在 390×844 视口检查首页、报告展开与证据、版本绑定反馈、真实消息提交处理器、文件选择上传、病例切换，以及访问撤回后原内容消失且仅保留授权记录。该服务没有模型或数据库，未纳入生产配置或仓库；测试只证明界面与请求绑定行为。后端既有单元与 PostgreSQL 集成检查由 CI 继续运行。

这不是官方效果验证、真人温度盲评或真实模型验收。开发令牌入口和仅接收合成材料的现有限制保留；品质推荐在线接口及长期随访仍需后续迭代。
