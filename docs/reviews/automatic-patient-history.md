# 自动承接就诊人历史对话

2026-10-16，替代手动记忆候选确认流程。移除“我的 → 关怀记忆”、聊天记忆设置、逐条选择来源及确认编辑器和前端客户端。自动模式的旧候选创建 / 确认接口返回 410，模型不再创建候选。

## 行为

注册账号在当前就诊人的关怀用途有效时，新对话自动检索该账号、该就诊人的历史用户消息。不需要长期用途开关、对话开关或逐条确认；此前明确撤回的来源仍排除。注册与资料用途说明同步说明自动承接，界面没有记忆设置板块。

正文仍保存在原有 PostgreSQL 对话记录。Semantix 固定版本的 BM25 / 中文检索内核只接收已通过数据库权限筛选的候选集，临时建立内存索引，不另建患者全局文件库。开发者全局 Semantix 与产品患者数据分开。

候选集包含最近 32 条和从全部可访问历史中按主题筛出的最多 32 条。每条至多拆成四个 1000 字检索块，匹配后回填完整原话，不截掉否定、人物和时间。普通对话最多提供 5 条 / 8000 字，优先保留最近两条作为承接和更正背景。主动 `search_history` 只返回主题命中，空问题才返回最近内容。

背景带原消息、病例和记录时间。它可能是疑问、假设、他人情况或已变化的旧状态，不能当作当前诊断或处方，不能覆盖病历。助手生成的回答不作为患者事实再次索引。模型可直接引用自动提供的真实消息，无需额外工具往返。

## 隔离与生命周期

- 检索前校验当前账号、家庭成员归属、就诊人和病例关怀用途。同一主体的另一个代理账号也不能读取该账号的私有历史。
- 仅使用已完成用户消息，排除失败消息、系统分析续答和其他就诊人内容。
- 复用原来源版本与 `chat_history_refs`，零 `memory_consent_version` 表示自动历史，不代表新增用途授权。旧确认记忆和正式报告保持原有版本约束。
- 每次模型调用前、最终落库前重查来源；最终短事务锁定来源及授权。生成中撤回会丢弃输出，返回 `MEMORY_CONTEXT_CHANGED`。
- 打开旧回答、重放请求和拼接近期上下文也检查依赖，撤回的内容不会通过旧助手回答重新进入模型。
- 明确关闭来源、关怀撤回 / 过期后停止引用；新授权仅使用授予时间之后的消息，不复活此前历史。没有独立文本副本绕过原消息删除。
- 检索器不可用时继续当前交流，不注入未经验证的历史。

当前自动模式针对聊天承接，不把全部历史自动变成正式报告医学证据。既有报告快照、复核、发布和来源撤回校验继续保留。部署人员可用 `ZHONGAN_AUTOMATIC_HISTORY_ENABLED=0` 回滚，普通界面无此设置。

## 验证

`tests/test_patient_memory.py` 以真实 HTTP、PostgreSQL 隔离 schema 和实际 Semantix 验证默认自动承接、就诊人 / 账号隔离、长消息、更正、较早主题、无需工具引用、旧接口退役、检索故障、来源撤回、过期、重新授权和生成中撤回。旧策略单独回归已有确认记忆及报告生命周期。

完整聊天集成已移除检索前的手动设置步骤；前端 DOM 测试验证切换成员不请求旧编辑接口，也不出现记忆板块。账号、附件、补问、服务推荐及就医记录测试继续运行。模型输出均为合成脚本，不据此声称临床准确性或真实模型记忆效果。
