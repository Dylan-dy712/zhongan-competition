# 在当前聊天完成模拟服务

2026-10-21，本地实现，未部署。

权益和互联网医院入口不再打开服务弹窗，而是继续向当前聊天发送需求。用户也可以直接提出预约或找医生，不必先点击卡片。

## 权益预约

暖暖查到公开目录里的服务后，在聊天里收集使用人称呼/关系、城市、期望日期时段；如有机构偏好一并保留。需求完整后展示摘要，确认后给出模拟预约编号和安排详情。没有指定机构时使用明确标注的示例服务点，不伪造真实机构预约。没有真实保单核验、名额占用、支付、短信或资料传送，不索取电话和证件。

## 医生接入

先收集症状、持续时间、当前严重程度及是否加重、既往诊断、医生偏好。支持以消化内科展示肠胃咨询场景。摘要确认后，同一聊天中显示“消化内科医生 · AI模拟（无真人接入）”，后续仍使用原输入框交流。聊天底部持续显示模拟角色，可随时结束并回到暖暖。不存在真人医生连接，也不承诺特定真实医生、排班、处方或诊断。

## 实现边界

- `manage_service_session` 是模型选择的服务工具，负责需求收集、确认、模拟预约、模拟医生角色和结束；没有前端关键词诊断或硬编码聊天回复。
- 服务状态是服务器生成的回答元数据，通过已有JSON回答持久化；从当前获授权聊天的已完成记录恢复。无新增数据库迁移，不从其他聊天或其他就诊人继承服务状态。
- 字段值需逐字来自本聊天用户消息；未知字段不能由模型自行补齐。每次服务工具调用重新提供最新临床上下文，并复用医疗分流规则。
- 急症、首次就诊、需线下评估、病情加重、肿瘤等限制不能通过模拟接入绕过。咨询中急症推荐会中止模拟医生状态，显示急救承接。
- 需求完整前不能确认；改变预约详情后重新核对；重复确认不新建模拟预约。仅当前最新回答的服务按钮可操作，忙碌中禁用。
- 已结束状态作为当前聊天状态保留，避免重新加载时恢复旧医生会话。普通后续回复不反复显示已结束服务摘要，暖暖也不会因历史医生角色被错误标记为医生。
- 历史服务卡恢复后使用当前组件，原来的服务弹窗入口全部改为当前聊天承接；原卡片内容仍保留来源和适用条件。

## 验证

后端回归：`python -m unittest tests.test_service_sessions tests.test_medical_services tests.test_conversation_agent tests.test_patient_followup tests.test_patient_memory -q`。

界面回归：在`apps/web`运行`npm run test:services`、`npm run test:followups`和`npm run build`。服务测试使用后端生成的合成状态，通过实际App组件验证预约收集、确认前不展示完成结果、忙碌保护、模拟医生接入和继续交流、重开聊天保留角色、结束回暖暖，以及全流程无服务弹窗或板块跳转。

模型语义选择使用受控响应测试；没有调用真实医生、预约平台或验证真实模型的完整多轮理解质量。

## 按公开范围匹配科室和咨询方向

2026-10-21补充：消化方向仅为示例。运行时使用`contracts/medical-services/online-care-scope.json`，包含来源、版本、科室支持层级、问题方向及182条药费目录证据；不依赖`output_dir`。前端使用服务器给出的角色标签，移除独立写死的六科标签映射。

- PLUS2026手册第15页明确列有内科、妇科、儿科。第16—18页为药费直赔疾病目录，不等于完整接诊范围。源PDF已在本地复读并保留哈希。
- [众安百万医疗2024文件第11页](https://open-cdn.zhongan.com/i-dm/2023-12-28/ehtobotbkmt/bwyl20241228.pdf)明确列有内科、外科、妇科、儿科；不同产品不自动共享权益。
- [众安2025-09服务文件](https://open-cdn.zhongan.com/i-dm-s/2025-9-22/x9r8vrl664r/qbhj9a9500b.pdf)涉及指定互联网医院中医问诊。文件还区分健康咨询和医生问诊，不能将健康咨询解释成疾病诊断。
- [众安全科视频文件](https://cdn-open.zhongan.com/product/market/Uy5LCGs2L80aGcAdemxEYO8P.pdf)所述版本有年龄限制且不支持科室转诊，不把它的限制或时段套入所有图文服务。
- [人保2026-01-27采购公告](https://ec.picc.com/cms/default/webfile/ywgg5/20260127/1200827589082480640.html)列有皮肤、全科等咨询和众安供应商，但外部采购合同不证明当前PLUS保单拥有独立皮肤科入口。

目录有20种科室或咨询路径标识，包括线下肿瘤和精神心理路径；这不是“众安开设20个线上科室”。消化、呼吸、心血管、代谢、神经、肾脏为内科下的问题方向，未取得独立科室号源证据；皮肤、眼部、耳鼻喉和口腔暂作全科分诊。儿科在接入前补充年龄。根据用户逐字提到的疾病检索目录可约束匹配方向，但不会从症状关键词自动确诊；未收录的疾病不直接判为不能咨询。

切换咨询方向会清除旧方向的症状摘要，补充本次情况后再接入，防止旧的胃肠问题被带入妇科或儿科咨询。癌症及精神心理需求始终遵守原有线下/专项边界；药费清单收录某条目不能覆盖明确排除规则。资料中未核实的实时科室、医生及排班继续标明未知。

补充测试包括：多疾病对应不同方向、用户未说过的诊断被拒、药费目录与接诊范围分离、焦虑条目不覆盖精神心理排除、换方向重新采集、旧会话来源补全。界面以多组后端合成状态验证不同角色、范围和来源展示，并确认不再沿用消化方向标签。打包、安装及更新脚本同步包含医疗服务目录；未执行真实服务器部署。
