# 上传、材料分析报告与正式关怀指引

用户确认了“AI 生成 → 自动校验 → 展示通过校验内容 → 待核实项单独提示”的产品流程。

`POST /v1/conversations/{id}/analyses` 使用现有 ChatMessage 契约和 request_id，持久化用户输入及附件、直接排队处理，无需聊天模型决定是否调用工具。同一请求重放返回同一 turn，完成后仍可用原有 continue 接口接续解释。失败的报告模型调用令新 run 为 failed；重试创建新任务，旧版生成失败但被标为 completed 的任务也不会继续复用。

弹窗同时突出显示整体百分比与“已完成 X / 5 步”，下方保留实际阶段列表。五步为识别材料、分析与核对、整理重点、校验来源、写好解读；并行的 extract/insights/reconcile 共用尚未完成的分析步骤。整体百分比按已完成步骤计算为 0/20/40/60/80%，只有对应任务的文字解读实际完成才显示 100%。提交和排队为 0%，未知阶段保留进度同步状态；等待时间不会自行推进百分比。上传百分比仍单独按服务器回执的文件数计算。收起窗口不取消后台分析，超过一分钟的阶段显示耗时提示；减少动画偏好会停用装饰动画。

conversation snapshot 增加 material_report，作为独立、自动核对的材料分析报告。其 ID 来自源报告、当前策略和校验后内容哈希，版本对应源分析报告版本；不会修改正式报告、审批记录或发布状态。每次读取重新验证会话所有者、当前授权/版本、上下文共享状态、最新任务、当前全部文档版本/哈希和报告生成成功状态。

材料报告重新校验原文支持，只展示通过严格匹配的病例事实/用户自述；病例事实改写未通过时，可展示保留限定的完整原文证据段。待审专业解释、服务建议、临床行动及缺乏来源的结论不返回给前端，按节显示待核实数量/缺资料提示。被拒绝或失效的源报告不可生成可读材料报告。聊天工具 read_material_report 读取相同结果并绑定证据，后续追问保持来源校验。

正式六节关怀指引继续使用既有审核和发布门槛。材料报告与正式指引同页分别标注，材料报告可立即阅读和逐节追问。既有模型生成失败显示失败并允许重新分析，不再把补齐的六段待确认模板呈现为成功报告。

验证包括自动核对单测、实际 HTTP/SQL 隔离集成、新上传/重放/跨身份访问、React 上传回执/分析阶段/报告/追问/失败重试，及移动端与桌面视觉检查。所有测试材料均为合成数据；这些工程测试不代表医学质量评测结果。
