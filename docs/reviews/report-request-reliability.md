# 报告请求超时修复

六份材料的报告调用在原 45 秒限制下于 45.21 秒连接失败；同一输入延长等待后在 49.49 秒返回 HTTP 200，六节 Schema 校验通过。原材料识别、字段提取与疑点分析成功，失败发生在报告请求。

报告请求改用 10 秒连接超时、最多 180 秒读取等待。传输重试与 JSON 修复共用最多两次调用；后续调用按 240 秒重试预算的剩余时间缩短等待，不额外叠加格式修复次数。Requests 的读取超时是等待响应数据的间隔，不是响应总耗时的硬截止。

超时（含 Requests 包装的 urllib3 ReadTimeoutError）、连接错误、HTTP 408/429/500/502/503/504 可以重试一次。认证、永久 HTTP 错误、响应结构错误不自动重试。保存错误分类、HTTP 状态、异常类型、耗时及调用次数，不记录异常字符串中的凭证或材料。生成报告失败仍为 failed，不伪造成功。

Worker 在阶段切换时续租五分钟，报告错误分类和可重试标记保存到 analysis_runs。材料提取和疑点分析保留原有请求等待设置，报告来源核验和医学审核门槛保持原有策略。

验证：test_report_llm.py 覆盖超过 45 秒的成功响应、包装超时、临时/永久 HTTP 错误、缩短重试等待、两次调用上限、JSON 修复审计及原调用默认值。PostgreSQL 会话集成验证进入报告阶段前已续租。
