# 报告补问与一键追问

材料解读和普通对话使用同一轮模型输出，附带 `clarification_questions`（最多两项）和 `suggested_questions`（最多三条）。报告优先补问最影响后续安排的一项实际缺口，例如复查时间、医院或当前用药；已有明确记录、刚回答过或表示暂不确定的内容不应反复询问。普通寒暄、排队中或无相关内容时可返回空数组。旧消息没有这些字段时仍正常展示。

最新回答的消息框底部展示补问和两三条个性化追问。补问支持快捷表态和自行填写；追问点击即发送完整消息。使用已有发送锁、请求幂等键、失败重试和授权链路。快捷操作不携带输入框中待发的附件，也不清空原有草稿；失败的补充输入仍保留。历史消息保留正文，操作区只显示在最新回答下。

用户补充信息通过 `patient_updates` 保存到原有 `conversation_turns.answer`，和成功回答原子提交，无额外数据库迁移。每项按复查时间、复查医院、用药、过敏或恢复情况分类，并必须保留当前用户消息全文；服务器丢弃不等于原消息的缩略或虚构表述，分析续答不能写入自述。否定、时间限定和“不确定”都保留为用户原话。用户自述不修改病历事实、不生成处方、不计算复查日期，也不自动创建提醒。

后续对话从有权限的原消息投影有限画像：同一账号、同一关怀对象、有效授权、成功的用户轮次；最多读取20个轮次，向模型提供最多12项、6000字符。按就医案件和字段保留最新更正，并带原消息ID、案件和记录时间。当前会话可使用自身补充；跨会话使用须双方开启历史回忆。撤回来源授权或关闭其历史回忆后，不再向其他会话提供其自述。旧案件自述明确标为历史数据，只用于个性化沟通和减少重复补问，不能升级为本次医学证据。

模型仍需判断何处存在信息缺口及用户是否在陈述自己的情况；逐字验证仅保证自述没有被删改，不能证明语义分类或医学结论正确。未识别和未读取的材料不作为缺失依据。具体复查时间和用药安排仍以实际医嘱为准。

验证：`python -m unittest tests.test_patient_followup tests.test_conversation_agent tests.test_model_workloads`；设置隔离测试数据库 `ZHONGAN_AUTH_TEST_DATABASE_URL` 后，额外执行真实SQL的持久化、重新连接、对象/账号隔离、更正、回忆和撤权检查。前端运行 `npm run test:followups --prefix apps/web` 和 `npm run build --prefix apps/web`。

共享报告草稿的 `patient_analysis` 也使用相同补问契约，复用到对话页时保留问题字段，不额外调用模型生成第二份报告。保持现有报告质量复核、来源校验和聊天附件流程。用户刚补充或表示不确定的字段，不在同一轮重复补问。

完整数据库回归由CI的原生PostgreSQL环境确认，临时兼容数据库的检查不能替代原生事务回归。部署遵循确切main提交及其成功CI产物的现有发布门禁。
