# 引用错误不再重写整份报告

一次线上任务在约33秒返回约1400字正文，但附带一条正文中不存在的引用。原逻辑携带完整病历、知识和旧草稿要求整份重写，第二次请求180秒超时，用户最终看到生成失败。

当报告 JSON 已通过校验，仅引用锚点不合法时，第二次请求只修引用。请求包含冻结的正文、出错索引和原链接的实际来源；响应只允许索引和新引句，不能修改正文、六节内容、行动或来源编号。新引句必须逐字唯一地出现在正文，引用来源仍经过授权与独立原文复核。根本未出现在正文的多余引用可明确返回 null 移除；真实存在但重复、跨行的正文片段不能用移除掩盖。不能交付没有任何引用的正文。

引用修复与草稿生成共享原来的最多两次请求和240秒阶段预算。引用修复读取最多60秒，千帆输出上限2048 tokens；失败不会再叠加第三次整份生成。原始草稿和实际修复响应分别保存，修复响应是元数据 patch，而非第二份报告；审计只记录索引和操作类型。阅读质量、概念解释和独立事实复核均保留，不能把修好格式当作内容审核通过。

验证包括正文和来源冻结、未知来源拒绝、有效引用保护、重复与跨行片段保护、孤立引用移除、空引用拒绝、60秒及两次调用上限、修复后仍拒绝不合格内容，以及真实失败草稿的无模型离线格式检查。真实模型联调仅使用虚构资料。

联调另发现阅读复核会把不同位置的原句拼接为解释证据，造成格式性误拒。阅读复核改为选择已有正文片段和已有引用的稳定编号，系统从原文解析为可审计的引句；不会自由重写证据句。未知编号、无实际解释或错误知识关联仍拒绝。可行动性与解释充分的语义评分继续由模型独立完成，不是靠编号或模板判通过。
