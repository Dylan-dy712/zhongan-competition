2026-10-21，本地实现与验证完成，尚未部署。

## 实现

模型依据当前就诊人及本次需求、已读取材料选择结构化参数：疾病类别、是否既往确诊、症状稳定性、线上目的、癌种和已知年龄。未知保留未知，不能从单纯科普、否定癌症或家属病史推断本人患癌。服务工具对参数应用确定的分流边界；不通过关键词诊断疾病。

- 急症仍最高优先，返回急救指引，无服务卡。
- 首次就诊、新发/加重、需检查治疗或已标记线下评估：只走线下。
- 肿瘤类别或专科或明确癌种：优先线下肿瘤专科，已有通用线上参数也不能绕过；缺地区则补问。已明确诊断时可补充绿通条件参考。体检、通用图文及普通购药卡不混入该路径。
- 肺癌/肠癌明确需要健康管理且未触发线下优先限制：可附加独立专项咨询卡，仍保留线下路径；其他/未知癌种不套用专项。
- 常见病/慢性病复诊：需已有诊断且稳定；资料不足先补问，不展示可复诊入口。线上处方另核对已知年龄，仍需医生判断接诊、疾病及药品范围。
- 一般健康咨询可提供入口，但说明尚未确认本病种适合线上诊疗，不能承诺线上确诊开药。精神/心理排除服务和未核实的其他病种转线下；缺专科名录时如实说明缺口。
- 肿瘤医院候选排序首先看专科匹配，再看地区片段。公私立偏好继续有效；综合医院仅作为明确标注的待确认备选，不把院名匹配当作具体癌种治疗能力验证。
- 保险指定机构、官网公开就医信息、历史绿通网络分别说明。线上专项不继承默认中高端权益假设。真实资格、号源、赔付仍需服务方核验，按钮继续为模拟入口。

界面展示分流原因和临床信息补问，避免卡片被抑制后只剩空白。旧对话服务卡不自动重算；新调用使用新版逻辑。

## 验证

- `python -m unittest tests.test_medical_services tests.test_conversation_agent -q`：49项通过，包括模型工具调用传递临床参数和服务元数据返回；模型响应为受控模拟，没有验证真实模型的疾病理解准确率。
- `npm run test:services`：通过，覆盖既有服务模拟流程，以及肿瘤专科、历史来源标记、线上卡抑制和复诊信息补问的实际React组件渲染。
- `npm run build`：TypeScript和Vite生产构建通过。

这批验证不等于真实临床效果评估、当前合作资格或个人保单核验，亦不表示线上服务器已更新。
