# 对话里的文字分析

患者上传材料后，分析结果由 AI 在原对话中写成连贯文字，不再跳往固定六节原文摘录页。用户选择温和清楚、像医护人员耐心解释的语气。内容主题与篇幅由本次材料决定，不为费用、治疗、情绪等主题硬填空节。

使用既有 analysis continuation 入口和原生模型对话。写作前按页读取获授权原始证据，每批最多 200 条、最多 6 批，正文总量不超过 28000 字符；各文档按片段顺序交错读取，避免 OCR 将正文拆成大量短片段时只看到第一份材料。超出读取范围须告知只解释已读部分。材料事实须附实际读取且可访问的证据引用，拦截已有危险建议模式，专业结论仍不能绕过发布门槛。来源引用验证不是医学事实正确性的保证。

独立的分析对话提示词要求保留疑似、否定、历史、用药阶段和费用口径，不猜身份、年龄、情绪，不把排班医师名单罗列成复诊安排。前端按 AI 的实际段落展示，引用集中折叠；不将内部操作和逐节审核计数作为主内容。旧材料报告链接返回对话，已审核发布的正式指引仍可单独阅读。

分析解释模式允许 180 秒读取等待及 16000 输出 token 预算，以容纳模型推理与正文；普通聊天保持既有配置。文字生成最多两次模型调用，仅允许一次 JSON 修复；原始来源预读后不再让模型重复走工具流程。专用续答路由的 Nginx 等待为 420 秒，覆盖两次慢请求；工具进度与每次写作前续租。模型完成后重新检查最新任务及文档版本/哈希，避免新材料上传后仍保存旧任务的解释。自然语言分析绑定 run_id，刷新复用已完成内容，失败可用同一请求重试。

续答的浏览器请求等待为 450 秒，覆盖 Nginx 的 420 秒等待；普通聊天和读请求保持原来的上限，写请求仍不自动重放。

旧原文摘录和正式六节报告继续在 API 中供来源审计及既有审核链路使用，不将其片段拼成新的 AI 文字正文。客户端展示真实模型输出，不使用合成演示内容替代。
