# 有来源的费用构成

REQ-03/04/05/07 的补充：Worker 新运行在既有五个核心字段外保存 `cost_breakdown`，通过既有案件 facts/events 接口读取。迁移015扩展字段类型；旧运行不回填或改写，旧五字段报告仍按原发布规则校验。

## 数据与来源

`CostBreakdown.fields` 按材料 ID、版本、页码和原文标签保留分类/支付汇总字段。元数据不足时只能以单个证据块为范围，不能把不同块默认为同张单据。字段包含 `FieldValue<CostAmount>`、字段级置信度/方法、原文 quote 与证据 ID；人民币以严格非负整数分保存。置信度为规则/模型未经校准的分数，不能当成验证后的正确率。

固定标签区分医疗总费、明细合计、收费分类、支付构成。药品费/药费/西药费等原文标签分别保留，不能直接相加；个人自费、个人账户、现金支付、统筹及保险后净支出分别记载，不转换成统一自付口径。明细或类别合计不再被通用“合计”规则误当作总费；单独“合计”保留为unclassified_total，不自动升格为医疗总费。

同范围同标签同金额合并来源，金额不翻倍；不同金额保留冲突和全部替代值。跨材料/版本/页面保持不同范围，页面也不等于已确认的单据身份。总费用与明细仅在相同物理范围内产生待核对候选，仍须确认单据、折扣、重复页和结算口径，不认定收费错误。

当前支持中文明确标签的分类/支付汇总行，不是完整药品逐行数量×单价账本。范围、项目完整性和重复单据未得到确认，因此 `completeness_status=not_established`，`item_sum_minor/self_paid_ratio=null`；缺失金额不填0。估算、范围金额、负数/退费、非人民币或不合法数字不会自动确认为支出。

## AI 与报告

现有结构化模型 Schema 增加可选 `cost_lines`，仍在一次抽取请求及既有修复预算内。模型提供原文标签、整数分和逐字 quote；服务校验标签与金额同时受该 quote 支持，并重查完整原文上下文，不能换用旁边单元格数字或删去“预计”等限定。

Worker 预备一次证据跨度，报告费用上下文与实际落库使用同一来源。关怀报告模型接收分类/支付字段、冲突、原文和范围限制，保留既有六节及原文引用放行规则；提示词版本分别为 medical-fields-and-cost-labels-v3 / six-section-care-report-v3。

费用构成进入医疗事件；嵌套金额冲突令事件关系不确定、运行待复核。发布再次核对当前运行的实际证据文本、标签/金额、文档版本和页码，不能仅凭保存的 quote 自称可信；冲突、伪造金额、跨文档或缺引用被拒绝，发布和触达记录不写入。

## 验证边界

单元检查覆盖分类/支付分离、重复和冲突、各范围隔离、不合法金额、模型改数/去限定、输出契约及发布原文重查。原生 PostgreSQL/HTTP 检查由现有 conversation/release 集成脚本验证：上传→Worker→结构化费用→授权证据读取→报告上下文；伪造/跨范围/嵌套冲突无发布副作用。

这些是合成样本的功能与安全验收。内部 eval_cli 当前仍按已有标注字段评分，新增费用构成尚需冻结金标和官方口径后才能计分；不能用旧总金额 F1 宣称费用构成达标。未验证真实模型费用抽取效果、真实 OCR 表格布局、人类盲评或官方KR1/KR4。医院映射、风险/医保/出院日期及获审规则特征仍需继续接入。
