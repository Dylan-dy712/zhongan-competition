# 就诊人记忆与报告：第二阶段

2026-10-16。基于最新主分支接入，并同步发布期间新增的服务推荐修复。保留现有病历分组、独立聊天附件、标题队列、OCR 缓存、知识检索和服务推荐。原工作目录的其他未提交改动不在本次发布中。

## 使用方式

在“我的 → 关怀记忆”为当前就诊人开启长期用途，确认需要保存的原话。聊天中的“本对话的关怀记忆”分别管理读入、来源导出和报告使用。

报告开关默认关闭，需要先开启读入，并明确告知来源将提供给具有该病例权限的报告复核人员。开启聊天回忆不会同时授权报告；关闭读入也停止报告使用。已有报告不会自动重写，需要重新生成。

记忆归属仍为账号＋就诊人。同一主体的其他代理账号不能通过报告或来源接口读取私有记忆；范围内医学审核人员仅在用户明确允许期间复核来源。

## 生命周期与边界

- 提交分析时，把最多 5 条 / 2500 字有效记忆及版本、来源消息、记录 / 确认时间、范围和有效期冻结进 `analysis_runs.context_snapshot`，参与输入哈希及现有不可修改快照保护。
- 报告没有自然语言检索问题，使用明确偏好和近期确认背景；普通聊天继续使用固定 Semantix BM25 检索。未接入患者记忆嵌入或医疗回答 L3 复用。
- `memory:<UUID>:v<version>` 是独立来源键，不加入病历 `evidence`。保留自述属性、时间和冲突提示，不能作为已核实诊断、当前处方或新医嘱。
- Worker 生成 / 保存、审核批准 / 更正、发布和读取均重查原版本、账号、就诊人、来源、长期用途及报告开关。引用列表必须与快照一致，清空 `memory_refs` 不能绕过。
- 含记忆背景的正式报告必须独立复核，原有材料、费用、专业知识和行动安全检查继续执行。自动材料摘录不把记忆自述显示成核对通过的医学材料。
- 更正、过期、撤回或关闭报告使用后，依赖它的草稿不能审核 / 发布，已发布报告和来源停止展示，发布重试也重查。历史正文不静默重写，不宣称追回已送达内容。
- 报告复用到聊天解读时登记相同记忆依赖，避免通过解读正文绕过撤回。

新增 `GET /v1/cases/{case_id}/reports/{version}/memory-sources`。所有者只能读取当前仍可见的已发布版本；范围内医学审核者可核对待审版本。返回原话、版本、来源、时间与 `medical_verification=false`，不向其他代理账号提供原话。

## 迁移与发布

最新主分支已经使用编号 023–027，因此发布分支的第一阶段迁移为 `028_patient_memory.sql`，报告开关为 `029_report_memory.sql`。原目录的 `023_patient_memory.sql` 从未部署，不复制到已使用该编号的线上序列。

首次迁移将旧版默认开启的回忆重置为关闭，不自动推定长期授权，不删除原始聊天。旧报告没有记忆快照时沿用原有权限检查。

发布包包含源码、迁移及同一 main push CI 的前端和 Linux amd64 检索器。校验检索器 ELF 平台与 `CI_REVISION`，上线前探测空语料协议；二进制变化按后端更新处理。沿用备份、数据库迁移、重启和失败恢复，不自动回滚业务数据库。

GitHub CLI 无法登录时，由已认证 GitHub 连接器核对精确 main push CI、取得该运行产物与 SHA-256，再使用相同校验和 SSH 发布逻辑。未通过 CI 或提交不再是当前 main 时不发布，不以本地构建替代 CI 产物。

## 验证记录

本机单元测试运行 465 项，通过 422 项，43 项因数据库 / 平台条件跳过。原生 PostgreSQL 16.15 随机隔离 schema 下，记忆与报告专项 26 项全部通过；审核、对话 / Worker 和发布集成检查通过。覆盖检索未命中后的报告工具引用、默认不读记忆的新对话正常打开、私有评估文字不进入共享进度元数据。使用合成材料和脚本模型，不调用真实医疗模型。

前端生产构建、导航及记忆 DOM 测试通过，报告开关覆盖默认关闭、聊天读入不自动授权报告、关闭读入停止报告使用。完整 CI 和最终线上读回以发布记录为准。

冻结样本的承接效果与成本对照尚未开展。已发布关怀计划转成新的 `care_plan_ref` 仍需独立确认和来源生命周期设计，本次不自动保存报告行动为长期计划。
