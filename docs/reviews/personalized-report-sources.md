# 用户表达与关怀报告来源

真实模型在合成出院小结测试中引用了用户的费用疑问和恢复担忧，但旧草稿只将 quote 关联到病历证据，用户表达与相关行动因缺少来源被丢弃。新版 `six-section-care-report-v4` 向模型提供明确的 `user_sources` 键，`source_quote` 绑定真实用户输入；病历仍用 `evidence_quote`，两类来源不互相替代。保留原始草稿作为审计输入，不原地增加来源。

当前用户来源仅来自案件中已存的 `user_context`，不是自动从所有聊天中提取；聊天上传建立的案件仍默认没有该上下文。将当前对话的关切纳入报告须进一步设计冻结的输入快照、身份/授权范围及版本引用，不能将可变历史或模型总结直接冒充用户表达。

来源键或逐字 quote 证明出处，不能证明模型改写忠实。改写用户表达须待复核，保留否定、担忧与实际症状的区别；不凭“你很焦虑”等话术推断情绪。模型标为 `service_suggestion` 的文字也待复核，防止临床/费用结论通过标签自动发布。服务建议仍由 LLM 结合用户材料生成，未替换为通用模板。

`report-safety-v3` 发布重新校验实际内容。未解决硬错误仍不能批准；可复核改写经对应报告版本的审批后才可发布。旧报告需按新政策重新生成，不在本次迁移中批量修改原文或审批记录。

`python -m scripts.check_report_provider` 是手动运行的真实配置模型测试，仅发送脚本内固定合成文本，检查六段、保留用户关切/相关行动、费用引文、没有编造提醒时间及无来源硬错误。只输出计数和检查状态，不输出模型原始响应或凭据；不会切换 mock 或自动补齐模型失败结果。它不是完整生产端到端验收、真实 OCR 测试、官方 F1、医学一致率或温度盲评。
