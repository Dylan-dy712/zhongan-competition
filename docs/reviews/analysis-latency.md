# 材料分析耗时优化

既有五份材料解读的实际输入为 65524 token，原文仅 7304 字符。OCR 的 857 条短片段重复携带文档 UUID、证据 UUID 和 JSON 字段；分析模式的历史上下文还携带旧回答的 usage、来源与模型元数据。现在按文档和页码组织原文，使用短来源编号，回复后映射回真实证据 UUID，再执行既有访问校验。患者接口继续返回真实引用，原文与限定词不裁剪；读取范围和超限说明保持原有约束。历史仅携带问题和回答正文。

字段提取和语义线索识别是独立网络步骤，改为最多两个请求并行。正式报告仍等待经过引用核对的字段、费用和人员信息，线索识别可与报告生成重叠。数据库连接、阶段续租、同意与输入校验、结果写入和发布审核仍由主线程执行；知识排除仍阻止对应模型调用。

记录匿名耗时与输入大小指标，后续可以区分解析、模型调用和写入时间。压缩单测验证所有原文、页码、来源映射完整，未知编号不可引用；并发单测使用同步事件验证真正重叠和依赖顺序。真实 PostgreSQL 审核与发布回归继续通过 CI 执行。

首次真实压缩测试将输入降至 11050 token，但仍用了约 45 秒，因为内部推理消耗 9584 token。根据 https://api-docs.deepseek.com/guides/thinking_mode/ ，官方 DeepSeek Flash 对直接原文提取和患者转述显式禁用思考；审核线索和正式草稿保留思考，设为 low。该参数仅用于 api.deepseek.com 的 deepseek-flash，其他服务或模型维持原配置。普通聊天配置保持原状。患者解读仍经过格式、来源、范围和危险建议校验，不将快速转述作为专业审核。

同组实际材料只读测试中，文字解读改用快速转述后约 16.4 秒（含一次格式修复），先前约 42.7 秒；857 条原文与 7304 字符全部保留。后台模型步骤旧配置并行测得约 129 秒，新配置约 41.8 秒，三步均 completed；这些是模型步骤的单次测量，不代表上传、OCR、排队和数据库写入的完整时延。重复引用去重后保留相同依据，不为重复编号再调用模型；独立来源超限仍须修复，不直接截断引用。

快速输出偶尔仍会抄录过多来源，因此唯一的一次格式修复显式告知错误字段与类型，并切换为低强度思考及原 16000 token 预算，避免在同一错误上重复快速生成。正文未通过校验时不会先交付，整个流程仍最多两次请求。
