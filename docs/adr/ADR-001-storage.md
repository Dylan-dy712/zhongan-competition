# ADR-001 原型期存储选型：文件产物 + SQLite，PostgreSQL 为生产切换目标

日期：2026-09-29 · 状态：已接受（原型期）

## 背景

spec.md（ZANH-SPEC-001）规定主数据库为 PostgreSQL，开发/集成/验收同引擎。开发机 Docker daemon 未运行，且比赛交付物为"方案 + 原型演示"（赛题明示不要求工程化上线）。

## 决策

原型期：运行产物为 JSON 文件（work/runs/<case>.json）+ 反馈追加 JSONL；不引入 ORM 层，API 只读文件。

生产切换（决赛前排期项）：PostgreSQL，表结构按 spec §4.2 语义（关系表 + JSONB 产物），当前 Pydantic 契约直接映射列定义；切换工作集中在 `app/main.py` 的 `_load_run` 系列函数替换为查询层。

## 理由

- 演示与评测均不依赖 DB 引擎特性；
- 文件产物天然满足"运行可恢复、失败可见、重跑幂等"（spec §7.1 的原型形态）；
- 省下的时间投入效果验证（权重 40%）。

## 后果与补偿

- 无事务/并发控制：接受（单写者批处理 + 原子替换写 `tmp.replace`）；
- 无 SQL 聚合能力：画像由离线脚本计算快照，本就不可变（spec §3.2）；
- 已在 solution.md §6 披露该偏差，不在任何材料中声称"已使用 PG"。
