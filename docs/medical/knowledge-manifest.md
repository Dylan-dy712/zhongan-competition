## 2. 条目 Schema

每条知识条目含 7 个字段（S2/S5 表格型条目以"表行 + 表后公共字段声明"等效呈现）：

| 字段 | 语义 |
| --- | --- |
| ID | `{病种码}-S{槽位号}-{两位序号}`，病种码 FX/FY/GX/YZ/TN；包内唯一，全库不跨包复用 |
| 适用范围 | 条目成立的前提情境（如"仅术后""仅成人CAP"） |
| 内容 | 可供生成器/规则引用的医学要点（不是面向患者的成段文案） |
| 锚定 | 使用该条时必须结合的病例事实（术式、部位、严重度、住院天数等）——支撑 QG-03 个性化验收 |
| 用途 | 服务的产品能力，取值：S1诊断解释段 / 术语解释动作 / 治疗回顾段 / 检查疑点标签 / 用药疑点标签 / 费用解释段 / 费用基线参考 / 出院指引缺口标签 / 康复计划段 / 复诊建议段 / 优先行动 / 治疗规范符合度画像 / 用药规则符合度画像 / 长期随访加分项 |
| 来源 | 指南/教材/规范名称；不编造页码与 DOI |
| 状态 | `draft-待医学审核` → 获准后改为 `approved-{审核人}-{日期}` |

统一安全约定：全部具体数值带 `【数值待医学审核】`（当前共 95 处）；用药条目一律含"缺少适应证材料本身不能认定用药错误"边界；危险信号三级分级 🔴立即急诊 / 🟠24–48小时内就诊 / 🟢常规复诊时告知；费用槽位不含任何金额。

## 4. 版本与获准流程

1. **当前**：v0.1.0-draft，全部 529 条待审核。条目只可用于开发夹具、提示词工程与内部演示（标注合成/草稿属性），不得作为患者报告的 `knowledge_refs` 来源。
2. **医学审核**：由医学审核人员逐包复核（重点条目见第 5 节），确认内容、数值、适用范围与排除条件。通过后条目状态改为 `approved-{审核人}-{日期}`，包版本号升为 `0.2.0` 并记入本清单。
3. **运行时引用**：报告 `knowledge_version` 必须指向已获准的包版本（spec 6.4）；未获准包版本不得写入 `knowledge_version`。运行时不得临时检索外部来源（spec 4.2）。
4. **变更控制**（spec 13.4）：知识内容、数值、来源或适用范围的任何修改都属于行为变更——升包版本号、重新审核受影响条目、回归受影响的痛点标签与报告验收用例。
5. **数值上线前阻断**：任何含 `【数值待医学审核】` 的条目在获准前必须被知识装配器排除或替换为定性表述，不得进入患者可见内容。

## 6. 使用红线（复述自官方命题与 spec）

1. 知识包是**接地与核对依据**，不是科普内容库；报告中引用知识必须走 `professional_explanation` claim 并带 `knowledge_refs`，与病例事实分开。一段报告若去掉病例事实仍成立，即疑似模板化（QG-03）。
2. 临床疑点只能输出"需核实线索"并进入复核，不得对患者宣称"医生开错药/做了非必要检查"（AC-10）。
3. 复诊日期：医嘱优先；医嘱未提供日期时 `due_at=null` 并给确认动作，知识只提供"通常节奏"（AC-09）。
4. 不得新增处方、虚构康复期限、保证疗效、替用户断言情绪（spec 6.4）。
5. 费用基线以官方脱敏数据集自建为准，知识包 S8 只做结构与口径解释（命题"无需额外数据源即可运行"）。
6. 材料命中 exclusions（如 CABG、1型糖尿病、脊柱肿瘤）时不得套用本包，转医学人工（各包头部已写明）。
